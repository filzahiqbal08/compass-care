Stage-by-stage notes

Data preparation

  1. Started from SITE_DASHBOARD.csv, the full HRSA federal listing of 129,141 clinic sites nationwide.
  2. Filtered to San Diego County ZIP codes, producing san_diego_sites.csv — 1,146 raw rows.

Milestone 1 — Excel

  1. Deduplicated and classified every site by hand in compass_care_milestone1.xlsx: 731 unique sites sorted into 5 site groups, tagged with services, and matched to organization-level languages and insurance notes. The Top_5_Nearest tab holds the full matching logic, checked against 14 hand-built test cases in the Answer_Key tab.
  2. Exported the finished tabs as flat files: sd_sites.csv (731 rows) and zip_centroids.csv (265+ ZIP centers).

Milestone 2 — Python backend

  1. Loaded both CSVs into compass_care.db, a SQLite database with indexed sites and zip_centroids tables.
  2. Rebuilt the Excel logic in finder.py — find_nearest() filters by group/service/language, measures real distance with the haversine formula, sorts, and backfills with nearby health centers if too few sites match. Verified 14/14 against the Excel Answer_Key.
  3. Wrapped that function in api.py (FastAPI), exposing it as a web endpoint — GET /sites — with CORS enabled so a browser front end can call it. Re-verified 14/14 over real HTTP requests.

Milestone 3 — Front end

  1. Built a plain HTML/CSS/JavaScript page (frontend/) that calls the API and renders real results as clinic cards.
  2. Confirmed end to end on a local machine: typing a ZIP code returns real, correctly-ordered results, including the fallback case.

Next — hosting

  1. Currently runs only on 127.0.0.1 — not reachable by anyone else. Deploying backend/ and frontend/ to Oracle Cloud and updating one line (API_BASE_URL in app.js) will give the app a real, shareable public address.
